# Beer Atlas 店舗追加 — GitHub Copilot運用

## 目的

店舗追加のたびにChatGPT等へリポジトリ全体の前提を説明せず、GitHub Copilot cloud agentだけで「最小入力 → 調査 → データ追加 → 検証 → PR」まで進めるための運用です。

## 最短運用

1. GitHubの Issues から **Beer Atlas 店舗追加** フォームを開く。
2. 店舗名、Google Maps URLまたは住所、人間が手動確認したGoogle評価（原則4.0以上）だけを必須入力する。メーカーや予約URL等は分かる場合だけ追記する。
3. `github.com/copilot/agents` でこのリポジトリを選択し、カスタムエージェント **Beer Atlas 店舗追加** を選ぶ。
4. プロンプトに `Issue #123 を処理して` のようにIssue番号だけ渡す。
5. Copilotが公開情報を調査し、店舗データを追加し、`pnpm ci` を通してPRを作る。
6. CI成功後、PRの根拠と差分を人間が確認してマージする。
7. `main` へのマージ後は既存のGitHub Pages workflowが自動デプロイする。

## Issueを使わず直接投げる場合

最小形は次で構いません。

```text
Beer Atlasへ店舗追加

店舗名: ひな鳥素揚げ 目黒 月鳥 自由が丘店
Google Maps: https://maps.app.goo.gl/...
Google口コミ: 4.2（人間が手動確認）
```

住所、メーカー、提供銘柄、認定、公式サイト、予約URL、緯度経度等はCopilotがアクセス可能な公開情報から調査します。短縮URLを展開できなくても店舗名等から一意に特定できれば続行し、特定できないときだけ不足情報を質問します。

Google口コミは4.0以上を原則の掲載候補基準としますが、その点数・口コミ件数はDBへ保存しません。

## Copilotが自動で判断するもの

- 既存店舗との重複
- 住所、エリアID・neighborhood ID
- `manufacturerId`、`brandIds`、`certifications` の既存マスターへのマッピング
- 店舗固有の提供銘柄・認定情報の根拠整理
- 信頼できる予約サービスかどうか
- 未確認項目を `未確認` のまま残すこと
- Google評価値をDBへ保存しないこと
- CI、format、build、test

## マスターデータの根拠

- ブランドマスターの `sourceUrl` はメーカー公式の商品・ブランドページを使う。
- 店舗メニュー、食べログ、Yahoo!マップ等は、その店舗が銘柄を提供している根拠として店舗の `sources` に利用できる。
- 店舗固有の掲載ページをブランドマスターの出典にはしない。
- メーカー公式根拠を確認できない新ブランド・新認定制度は推測でマスターへ追加しない。

## PRの機械ゲート

新規店舗を追加するPRでは、PR本文に次のチェックを入れないとCIが失敗します。

```markdown
## Beer Atlas 店舗追加チェック

- [x] Google Maps評価4.0以上を人間が手動確認
- [ ] Google Maps評価4.0未満だが例外掲載を人間が明示承認
- [x] Google評価点・口コミ件数をDBに保存していない
- [x] 提供銘柄とメーカー認定を分離して確認
- [x] 予約リンクは許可プロバイダーのみ
- [x] pnpm ci 成功
```

4.0未満の例外掲載時だけ、1つ目ではなく2つ目をチェックします。

## 人間が事前に確認するもの

- Google Mapsの口コミ評価（原則4.0以上）

店舗の実在、メーカー、銘柄、認定、予約導線等はCopilotが調査します。調査不能な情報だけ人間へ確認を戻します。

## 人間がPRで最後に見るもの

- 別店舗を誤登録していないか
- 「提供」と「公式認定」を混同していないか
- 予約リンクが意図したサービスか
- 根拠URLが対象店舗・メーカーの正しいページか

## マージについて

Copilotは店舗追加PRを自分でマージしません。CI成功と人間の最終確認を必須運用とします。GitHubのRuleset / Branch protectionでCIをRequired status checkに設定すると、失敗中のPRをUI上でもマージできない構成にできます。
